## D-030：模擬売買の規則

- 日付：2026-11-01
- 状態：**Accepted**（オーナーが売買単位・締め時刻・配当を選び、推奨案をPRで承認）
- 決定：日次で、翌営業日の8:30に注文を締め、9:00の始値で成行約定する。AIは1日1回だけ注文票を確定でき、確定後は変えられない。現物だけ、100株単位、手数料0円、初期資金1,000万円。始値がつかない日は約定させず失効。分割は権利落ち日に株数を調整し、配当は権利落ち日に税引前で現金に加える。詳細は`docs/PAPER_TRADING_RULES.md`。
- 理由：決算発表の多くは15:00以降なので、翌朝に締めればAIが反応できる。始値は板寄せで1つに決まり、日中の値動きのデータが要らない。100株単位は現実の単元株に合わせた（オーナー判断）。注文票を1日1回・変更不可にするのは、あとから都合よく直したという疑いをなくすため（オーナー判断）。引けの注文、指値、ザラ場中の売買には広げない（オーナー判断）。
- 修正（2026-11-01、オーナー承認。#24）：分割と配当は、権利落ち日の寄り付き前ではなく、**権利落ち日の前営業日の評価のあと**に反映する（株数の調整と、税引前の現金の加算）。確定（8:30）のあとで株数が変わり、注文票に書いた株数の意味がずれるのを防ぐため。
- 影響：100株単位と1,000万円では値がさ株を買えないため、取引対象を選ぶときに考慮する。データの取得元はP-001で決める。

## D-031：祝日の取得元

- 日付：2026-11-02
- 状態：**Accepted**（オーナーが方針を承認。取得方法だけの決定で、株価・IRデータはP-001）
- 決定：祝日は内閣府の「国民の祝日」CSV（`https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv`）から、`npm run holidays:update`で`apps/web/src/holidays/holidays.json`（2020年以降、年ごと）を作り、リポジトリに置く。JSONは手で直さない。取得元CSVのSHA-256（`sourceSha256`）と、一覧の中身のSHA-256（`contentSha256`）を記録し、更新はPRで人が確認してから入れる。今年までの祝日が取得元で変わったときは、`--allow-past-changes`を付けない限り書き込まない。手元のCSV（`--file`）は`--check`にだけ使える。台帳には`holidaysFor(from, to)`の結果を引数で渡す。返す一覧は、範囲の外の年の日付を引くと例外になるので、前営業日・翌営業日を探して年をまたいでも、黙って営業日にしない。JSONは取得元のCSVのとおりで、土日や年始と重なる日も含む。土日と12月31日〜1月3日は台帳が別に判定する。
- 理由：公的な一次資料で、費用がかからない。リポジトリに置くので、過去の日付の判定を同じ一覧で再現でき、取得元の変更や停止で台帳が止まらない。どの一覧を使ったかは`HolidayTable.contentSha256`で外に出す（取得元の改行や対象外の年の変更では変わらず、手で直すとテストで分かる）。台帳に接続するPRで、約定・評価の記録にこの値を残す。
- 費用：0円。依存の追加なし（Node標準の`fetch`と`TextDecoder`）。
- 権利：内閣府サイトの利用規約（政府標準利用規約に準じて出典の記載が要るか）は未確認。祝日は事実の一覧で、台帳の内部でだけ使う。`holidays.json`（名称を含む写し）は非公開のリポジトリ（2026-11-02に確認）に置いており、`source`に取得元を書いている。**リポジトリの公開や、画面・APIで第三者へ示す前に、利用規約と出典の書き方を確認する**（P-001と合わせる）。
- やめ方：`holidays.json`の形式（`years`に`[日付, 名称]`の並び）を保てば、取得元を東証の休業日カレンダーなどに差し替えられる。
- 限界：臨時休場（システム障害による終日売買停止など）は含まれない。起きたときは、CSVとは別に休場日を足す仕組みを決める。毎年2月ごろに翌年分が出るので更新が要る（自動でPRを作る仕組みは別PR）。

## D-032：監査用イベントログの形式

- 日付：2026-11-03
- 状態：**Accepted**（2026-11-03、オーナーがPR #38で承認。データの誤りは調整のイベントで直す、本文はログの外に置き消せるようにする、AIは自分の投稿を訂正・非表示にできない、の3点を含む。#22）
- 決定：追記だけのイベントログを正本とし、現金・保有・損益・ランキングはログを決定論的に再生して得る。全イベントに抜けのない通し番号（`seq`）とサーバーの記録時刻を振り、参照は前のイベントにだけ許す。種類ごとに書ける者（AI・システム・運営者）を決め、AIは自分の投稿を訂正・非表示にできない。同じ注文票の2回の約定や、同じ日・同じ公表の分割・配当の2回の反映は、一意キーで書き込みの時点で拒む。始値は締めの後にしか記録できない。注文票の確定は、記録する時刻で同じトランザクションの中で検証する。各イベントは RFC 8785 で正規化し、前のイベントのハッシュを含む SHA-256 の連鎖でつなぐ。誤りは書き換えず、訂正・調整・非表示・停止のイベントを足す。入力データの誤りは、正しい値で再生した口座との差を調整のイベントとして足し、AIの判断（注文票）は直さない。記事・価格・分割配当の内容・投稿の本文はイベントの外に置き、イベントには乱数を前置きしたハッシュだけを書く。ログはP-001の決定まで第三者に出さない。詳細は`docs/EVENT_LOG.md`。
- 理由：「後で知った情報で前の判断を作る」ことを、順序と参照の形で不可能にするため。台帳の関数を純関数のまま保ち、二重の反映は追記の処理の一か所で防ぐため。法的に本文を消す必要が出ても、連鎖を壊さずに消せるようにするため。
- 費用：0円。依存の追加なし。保存先（DB）はP-004（#20）で決める。
- 限界：DBに書ける人はログ全体を作り直せる。外部に `seq` と `hash` を示す方法は未決。
- やめ方：形式は保存先に依存しない JSON なので、DBを替えても移せる。
- 修正（2026-11-04）：祝日の一覧の版と取引対象は、運営者が書く `holidays.adopted`・`universe.set` でログの中で替える（`docs/EVENT_LOG.md` §3.5）。照合は各イベントの時点で採用していた版でやり直す。元の「記録した版といまの版が違えば、営業日の判定をやり直さず報告する」は、年1回の祝日の更新で過去のログ全体が照合できなくなるのでやめた。一覧を替えても、ログがもう使った日付までの休場日は変えられない。評価と引け後処理の記録の `contentSha256` と使った `market.closed` の `seq` は、ログの順序から決まるので書かない。

## D-034：外側とのつなぎ目の契約の規則（Clock・EventStore・MarketDataPort・LlmPort）

- 日付：2026-11-04
- 状態：**Accepted**（2026-11-04、ownerがPR #61をマージして承認）
- 決定：契約の型は`apps/web/src/contracts/`、契約テストと偽物は`apps/web/tests/contracts/`（`describeEventStoreContract`・`describeMarketDataContract`・`describeLlmContract`。platformが自分の実装に同じテストを当てる）。規則は次のとおり。
  - **時刻：** `recordedAt`は保管が持つ`Clock`（1つ）から、直列化した追記の中で一度だけ決める。呼び出し側が実行時に`recordedAt`を渡しても**無視**する。本番の`fetchedAt`は、取得したときに`Clock`から取り、取得元の値や入力から取らず、後から過去の時刻を作らない
  - **市場データの窓（先読みの防止）：** `asOf(at)`の窓は、`publishedAt < at`かつ`fetchedAt < at`の観測だけを返す（等号を含まない）。公開時刻が不明な観測は返さない。改訂は元を書き換えず、観測した版をすべて残し、改訂の`publishedAt`は取得元の改訂時刻（なければ最初に観測した時刻以上）。バックフィルは、取り込んだ時刻より前の窓には見えない。`at`が現在時刻より後なら`asOf`は同期で`RangeError`
  - **LLMの費用：** `maxCost`は1以上の安全な整数、`dailyCostLimit`は0以上（0は「呼ばない」）。外れたら呼ばずに`RangeError`。判定と予約は原子的で、提供元の呼び出しは直列にしない。実費は切り捨てずに記録する。課金されたか分からない失敗（例外・通信断を含む）は、`ok:false`で返し、`maxCost`を費用に残す。換算（#21）で切り上げたあと、NaN・負・Infinityのときだけ`maxCost`を費用にする。暦日は`startedAt`（日本時間）で決める
  - **保管：** 追記だけ（更新・削除の口なし）。`EventReader`が返す`LogEvent`は凍結済みか複製で、書き換えても保管に影響しない（型は深い読み取り専用にしない。`replay`の引数に響くため）。Promiseを返す口の`RangeError`はreject
  - **試運転：** `OrderlessEventStore`は型の上の便宜で、保証ではない。保証は`runner`（#29）が、`commitSheet`を持たない凍結したオブジェクトを返す工場関数で作る
- 理由：platformとwebが同じ型だけに依存して並列に進められる。AIの発言・注文・約定を後から検証でき、先読みと費用の取りこぼしを仕組みで防ぐ（`AGENTS.md`の不変条件）。独立した`code-reviewer`を3回通し、高0・中は反映済み
- 費用：追加の契約・依存なし
- やめ方：`src/contracts/`と`tests/contracts/`を外せば、型への依存がなくなる。実装は契約に依存するだけなので、置き換えられる
- 限界：`src/contracts/`は`check-purity.ts`の対象外（純関数の決まりを構文木で検査していない。対象にするかはownerの判断待ち）。試運転の保証と、`settings`・`messages`だけを送るテストは、#29と#21の後

## D-035：観戦画面のデータの出どころ（当面はゴールデンログ）

- 日付：2026-11-04
- 状態：Proposed（ownerのマージで承認）
- 決定：保管（#25）と仮のAIの通し（#27）ができるまで、観戦画面（`src/app/`）は、固定シードのゴールデンログ（`apps/web/tests/fixtures/golden.ts` の `buildGoldenLog(20261104)`）を `src/view` の `buildView` に通したものだけを表示する。画面は組み立てのたびに、価格の出典が `fixture:synthetic` で、銘柄が架空のものだけであることを確かめ、違えば表示しない。全ページに「架空のデータによる模擬売買です。実際の運用実績ではありません。」を出し、`noindex`。内部の確認用で、公開・デプロイはしない（P-001が未決）
- 差し替え方：#27 で保管ができたら、`src/app/data.ts` の出どころだけを、保管の `EventReader`（読むだけの口）に替える。`buildView` は「イベントの列と本文」を受け取る形のままなので、表示の側は変えない。ゴールデンログは、その後も表示のテストの正本として残す
- 理由：架空のデータで、画面と表示の変換を先に固められる。実データと権利の判断を待たずに進められる
- 限界：アプリのコードが `tests/fixtures/` を読み込む（差し替えるまでの間）。`tests/fixtures/` の変更が画面に直結するので、CODEOWNERS に入れるかをownerが判断する

## D-036：観戦画面の見た目（ネオン・アリーナ）と書体

## D-042：実データをやめ、AIの売買で価格が決まる人工市場にする

- 状態：Accepted（owner、2026-11-05）

- 決定：**架空の国の経済（景気・金利・物価・為替）と出来事が架空の企業の業績を動かし、その企業が上場する架空の市場** を作り（人工の世界・経済・市場）、価格は **参加者（AI 投資家・マーケットメイカー・ばらばらの参加者）の注文の板寄せ** で決める（案B）。実在の企業・価格は使わない。設計は `docs/MARKET_DESIGN.md`。最小（段階0：企業6社・業績・決算・板寄せ・流動性・規則のAI）で公開し、経済・出来事・為替・LLM の AI を段階的に足す

- 影響：D-038 の取得元（J-Quants・yfinance）は使わない。D-030（模擬売買の規則）のうち、約定の価格と注文の種類を替える。記録・台帳・AI の実行・画面・保存先（D-040）・LLM（D-041）は続ける
- やめ方：価格の決め方は約定の部分に閉じているので、実データの取り込み（`MarketDataPort`）に戻せる

# Project Charter

最終更新：2026-10-29

## 1. プロジェクトの目的

GUILD MARKETは、変化する情報の中で未来を予測し、市場価格を手がかりに判断を更新する体験を、ゲームとして提供するプロジェクトです。

金融商品の知識を一方的に教えることではなく、次の能力を体験的に扱います。

- 情報の信頼性を考える
- 人気と実際の成功可能性を区別する
- 一つの情報だけで判断しない
- 他者と相談して意思決定する
- 新情報によって仮説を修正する
- AIの結論ではなく根拠と未確認事項を見る
- 結果だけでなく判断過程を振り返る

## 2. プロダクトの定義

> 複数の情報から未来を予測し、市場価格を手がかりに判断を更新する、予測ゲームプラットフォーム。

市場は人工市場です。プレイヤーと約100のNPC商会が同じ市場で売買し、注文はラウンドの締切ごとに一斉に約定します（D-024）。ニュースを読むだけでなく、ほかの商会の動きを読むことがゲームの中心になります。

親子向け、学校向け、個人向けを別々のゲームとして作りません。共通のゲームコアに、異なるセッション形式とシナリオを載せます。

## 3. 名前の階層

- **F-Sports**：予測を競技として楽しむ考え方／カテゴリー
- **GUILD MARKET**：教育向けゲームシリーズおよび共通システム
- **王国一のギルドを見抜け**：銀行イベントで使う第1シナリオ
- **ゲスっち**：将来的な送客、プロフィール、ランキング、市場連携の候補

## 4. 最初の対象

- 対象：小学4〜6年生と保護者
- 規模：親子30〜50組
- 時間：90分
- 主催候補：銀行
- 利用端末：親子で1台
- 金銭：ゲーム内ポイントのみ。現金・実在金融商品は扱わない

## 5. 解く課題

従来型の金融教育イベントは、説明を聞き、一度選び、結果を見るだけになりやすいという仮説があります。GUILD MARKETは、短い間隔で判断と修正を繰り返し、親子や会場全体が参加する体験へ変えます。

## 6. プロダクト原則

### 6.1 操作は一つ、判断は深く

操作の中心は最後まで「買う・売る・保有する」です。複雑さは機能数ではなく、ニュースの質、情報差、価格、群集心理から作ります。

### 6.2 一つのゲーム、複数の遊び方

ライブイベント、学校授業、家庭、一人プレイで、ゲームコアを分岐させません。

### 6.3 少人数でも成立する

市場システムが流動性を提供し、一人でも売買できることを前提にします。王国の商会100（NPC）が市場の動きを作るため、ライブ参加者の取引は体験を豊かにしますが、成立条件にはしません。

### 6.4 人気と結果を分離する

市場価格は参加者の予測を表しますが、取引量によってギルドの成功自体は変わりません。最終結果はレビュー済みシナリオで決定します。

### 6.5 体験後に現実の言葉へ翻訳する

本番中は金融用語の講義を挟まず、最後の振り返りで、分散、流動性、群集心理、情報リスク、利確・損切り、仮説修正へ接続します。

### 6.6 子どもの安全とプライバシーを優先する

必要最小限のデータのみを取得し、イベント／チームの仮名IDを基本とします。秘密情報、児童・保護者を直接特定する情報を開発・分析用ログへ入れません。

## 7. 最初に検証する仮説

優先順は次のとおりです。

1. 売買だけの操作でライブイベントが盛り上がる
2. 情報差によって親子の会話と共同判断が生まれる
3. 参加者が新情報によって予測を修正する
4. イベント後に一人用シナリオを実際に遊ぶ
5. 行動ログから教育効果の兆候を評価できる

## 8. 初期スコープ

### 含む

- 銀行への提案会議で、5〜6人が各自のスマートフォンで対戦する約5分の提案会議MVP
- 親子30〜50組の90分イベントMVP
- 4ギルド、練習＋本番4幕
- 売買、市場価格、ニュース、情報差、調査券
- 運営画面、会場画面、結果、市場リプレイ
- イベント後に一人で遊べる追加シナリオ1本
- イベント、継続利用、教育評価のためのログ

### 含まない

- 王国経営、建物建設、マップ移動
- RPG戦闘、キャラクター育成
- 複数通貨、アイテムインベントリ
- 実在株価、現金、暗号資産、課金
- ユーザー間チャット
- 自由会話AI
- ネイティブアプリ
- 永続するオープンワールド
- 初期イベントでの実行時生成AI

## 9. 成功の定義

イベント満足度だけではなく、イベント後の行動まで確認します。詳細な定義は`DATA_AND_EVALUATION.md`を参照してください。

- イベントが安全かつ停止せず完了する
- 多くの参加者が複数回売買する
- 親子双方が判断理由を話す
- 参加者が途中で予測を変更する
- 「また遊びたい」という意向が高い
- イベント後の追加シナリオが実際に開始・完了される

## 10. 現在の制約

- 初期開発はCodex、Claude Code、人間の開発者で進める
- まず提案会議MVPを作り、同じアプリとエンジンを銀行イベントMVPへ広げる
- 技術構成はD-027で決定。クラウドの契約は別途承認する
- サーバーコストより、開発、コンテンツ制作、テスト、当日運営を主要コストとして扱う
- 銀行から特定の金融テーマや禁止表現は、現時点では提示されていない

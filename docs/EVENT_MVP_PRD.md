# Bank Event MVP — Product Requirements Document

最終更新：2026-09-02
状態：Draft

## 1. 概要

銀行主催の金融教育イベントで、小学4〜6年生と保護者30〜50組が、予測商会として4ギルドの成功可能性を考え、ニュースに応じて成功証を売買する90分のライブゲームを実施します。

イベントMVPは、提案用プロトタイプとは別の成果物です。本番では複数端末同期、運営制御、再接続、監査可能なログを必要とします。

## 2. 目的

優先順：

1. 会場全体が盛り上がるライブ体験を成立させる
2. イベント後も遊びたいという意向を得る
3. 追加シナリオへの実際の再訪を計測する
4. 親子の会話、予測修正、情報選択をログと観察で評価する
5. 進行停止や重大な取引障害なく完了する

## 3. 対象と前提

| 項目 | 前提 |
| --- | --- |
| 対象 | 小学4〜6年生と保護者 |
| チーム数 | 30〜50組 |
| 端末 | 親子で1台のスマートフォンまたはタブレット |
| 時間 | 90分 |
| 参加方法 | QRコードまたは短い参加コードを想定 |
| 初期資金 | 1,000G |
| 投資対象 | 4ギルド |
| ラウンド | 練習＋本番4ラウンド |
| 取引 | 買う・売る・保有する |
| 結果 | レビュー済み固定シナリオ |

## 4. ユーザーロール

### 参加チーム

- 商会名を入力する
- 現在価格、現金、保有状況を確認する
- ニュースと役割別情報を読む
- 予測と確信度を記録する
- 市場が開いている間に売買する
- 調査券を1回使用する
- 結果と自分の判断履歴を振り返る

### 子ども：スカウト

- 人気、評判、発言、住民反応を受け取る
- 親の助言を聞き、最終的な売買操作を行う

### 保護者：アナリスト

- 費用、過去実績、資金、技術・制度リスクを受け取る
- 子どもへ助言する
- 端末の最終操作は原則行わない

### 運営者

- 現在ラウンドとイベント状態を進める
- 市場を開始・停止する
- ニュース、調査結果を配信する
- カウントダウンを制御する
- 接続状況を確認する
- 必要時にポイントや取引を修正・取消する
- 最終精算を実行する
- 緊急停止する

### 司会／実況者

- 会場へ物語と市場状況を伝える
- 特定ギルドの購入を誘導しない
- 本番中に長い金融講義を行わない
- デブリーフで体験を現実の概念へ翻訳する

## 5. セッション構成

正確な分数はリハーサルで調整します。

| 区間 | 目安 | 内容 |
| --- | ---: | --- |
| 導入 | 3〜5分 | 世界観、目的、安全説明 |
| 練習 | 5分 | 模擬レースで売買を理解 |
| 第1幕 | 15分 | ギルド紹介、最初の予測と投資 |
| 第2幕 | 12分 | 親子の情報差、相談、売買 |
| 第3幕 | 12分 | 事故の噂、急落、市場停止 |
| 第4幕 | 12分 | 調査、AIレポート、一次情報、最終売買 |
| 決算・表彰 | 15分 | 精算、ランキング、各賞 |
| デブリーフ | 10分 | 市場リプレイ、金融・AIリテラシーへの翻訳 |
| 余白 | 4〜6分 | 接続、移動、進行調整 |

合計は台本確定時に90分へ調整します。

## 6. 参加者体験の必須要件

### 6.1 参加

- イベントを選ぶ操作を必要とせず、配布されたコードから対象イベントへ入れる
- 商会名を入力できる
- 児童の本名を要求しない
- 二重参加や誤再読込を可能な範囲で防ぐ
- 再読み込み後も同じチームとして復帰できる

### 6.2 市場

- 4ギルドの現在価格を表示する
- 現金、保有口数、評価額、総資産を表示する
- 数量または金額を選んで購入・売却できる
- 注文前に費用または受取見込みを確認できる
- 注文結果を明確に表示する
- 市場停止中は注文できず、理由を表示する
- 残高不足、保有不足、重複注文を拒否する

### 6.3 情報と予測

- 共通ニュースを表示する
- 子ども／保護者向け情報を区別する
- 各ラウンドで本命ギルドと確信度を記録できる
- 判断理由を短い選択肢＋任意コメントで記録できる案を優先する
- 未読情報が分かる

### 6.4 調査券

- 残り枚数を表示する
- ゲーム全体で1回だけ使用できる
- 調査先を選択できる
- 使用後は取消・再利用できない
- 選んだ情報源と取得内容を記録する

### 6.5 結果

- 成功ギルドを表示する
- 保有成功証を精算する
- 最終資産と順位を表示する
- 最初と最後の予測を比較する
- 自チームの主要取引を振り返る
- 一人用追加シナリオへのQRコードまたはリンクを表示する

## 7. 運営画面の必須要件

- 現在の状態、ラウンド、残り時間
- 次の状態への手動遷移
- 市場開始／停止
- ニュース配信
- 調査レポート配信
- チーム接続状況
- 注文受付状況とエラー概況
- ポイントの手動修正
- 個別取引の取消または補正
- 最終結果の確認と精算
- 緊急停止
- 操作履歴

不可逆な操作には確認を設けます。運営操作は誰が、いつ、何を行ったか記録します。

## 8. 会場画面の必須要件

- 4ギルドの現在価格
- 価格チャート
- 取引件数または市場の勢い
- 残り時間
- ニュース速報
- 暫定ランキング
- 市場停止状態
- 決算結果
- 市場リプレイ

他チームの個別保有銘柄は表示しません。参加者の本名も表示しません。

## 9. 市場要件

- 市場システムが売買相手となり、注文相手の存在を必要としない
- 価格は市場全体の注文に応じて変動する
- 市場状態はサーバー側を正とする
- 残高、保有、注文可否、精算はサーバー側で検証する
- 同じ注文が重複処理されない仕組みを持つ
- 市場停止後に到着した注文を拒否する
- 全注文と価格変化を再生可能な形で記録する
- 結果は市場価格や注文量によって変わらない

正式アルゴリズムは未決定です。LMSRを候補として、流動性パラメータ、分かりやすい購入単位、価格操作耐性をプレイテストで決めます。

## 10. イベント状態

```text
LOBBY
→ TUTORIAL
→ BRIEFING
→ FORECAST
→ MARKET_OPEN
→ MARKET_FROZEN
→ NEWS
→ MARKET_OPEN
→ SETTLEMENT
→ REPLAY
→ RESULT
```

実際にはラウンドごとに`FORECAST`、`NEWS`、`MARKET_OPEN`、`MARKET_FROZEN`を繰り返します。遷移は運営者のみが実行し、参加端末は現在状態を復元します。

## 11. 非機能要件

### 性能・同期

- 50チームの同時利用を対象とする
- 注文後の価格反映は通常1秒以内を目標とする
- 会場画面と参加画面の価格・市場状態を同期する
- 全端末が毎秒書き込みを行う設計を避ける

### 信頼性

- 通信切断後に自動復帰する
- 再送による二重注文を防ぐ
- 精算を複数回実行しても結果が重複しない
- 市場停止、精算、結果発表に運営者の確認を設ける
- 最低限の進行を手動で継続できる運用手順を持つ

### 会場運用

- 運営端末は可能なら有線接続する
- 会場Wi-Fiの事前負荷確認を行う
- 参加コード、ニュース、価格、結果の代替表示を用意する
- 重大障害時に市場を一括停止できる
- 紙の役割別情報カードをバックアップ候補とする

### アクセシビリティ

- 小学生が読める語彙と文字サイズ
- 色だけに依存しない上昇・下落表示
- タップ対象を十分な大きさにする
- 数字と文章を詰め込みすぎない
- 読み上げや会場アナウンスと矛盾しない

### セキュリティ・プライバシー

- 児童の本名、住所、学校名などを必須にしない
- イベントコードから運営権限へ到達できないようにする
- 運営機能を参加者機能から分離する
- ログへ秘密情報を残さない
- データ保持期間と削除方法を本番前に決める

## 12. 初期データモデル

- `Event`：イベント本体
- `Team`：親子チーム
- `Market`：4択市場
- `Outcome`：ギルド／結果候補
- `Holding`：保有成功証
- `Transaction`：売買履歴
- `Forecast`：各ラウンドの予測と確信度
- `NewsEvent`：ニュースと配信履歴
- `Investigation`：調査券の使用
- `Round`：ラウンドと進行状態
- `Settlement`：最終精算
- `Score`：資産、予測、リスク指標
- `OperatorAction`：運営操作履歴

これは論理モデルであり、DBテーブルを確定するものではありません。

## 13. MVP対象外

- 王国経営、建設、探索、戦闘、キャラクター育成
- 実在金融商品の価格連携
- 現金、暗号資産、課金
- ユーザー間チャット
- 自由会話AI
- 実行時に生成されるAIニュース
- ネイティブアプリ
- 複数イベントを横断する一般公開ランキング
- 本格的なCMS
- 複雑な自動表彰判定
- ゲスっちとの深い市場統合

## 14. リリース受け入れ条件

- 親子50組相当の負荷試験を通過する
- 重複注文、市場停止後注文、残高不足を正しく拒否する
- 切断・再接続後に現金、保有、状態が復元される
- 運営画面から全状態を進行・停止できる
- 会場画面と参加画面が同期する
- 最終精算を安全に完了できる
- 全市場イベントをリプレイできる
- 緊急時手順を含む運営リハーサルを完了する
- 計測イベントとプライバシー項目をレビューする
- 追加シナリオへの導線を表示できる

## 15. 未決事項

- イベント開催日と正式な主催者
- 正式な市場アルゴリズムと流動性パラメータ
- 1注文の数量・金額UI
- 親子の情報差を紙と端末のどちらで実現するか
- 参加復帰用トークンの方式
- 運営者の認証方式
- 技術スタック、ホスティング、DB
- ログ保持期間と同意文言
- 銀行ブランド、監修、免責表示

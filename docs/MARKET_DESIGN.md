# 人工市場の設計（D-042）

更新：2026-11-05
状態：**Proposed**（方向は D-042 で owner が決定。この文書の既定値は lead の提案で、owner がマージで承認する）

AIたちの売買そのものが価格を決める、架空の株式市場を作る。実在の企業・実在の価格は使わない。これまでの記録の仕組み（`docs/EVENT_LOG.md`）・台帳（`docs/PAPER_TRADING_RULES.md` のうち、口座・売買単位・現物だけ・配当と分割・評価）・AI の実行・画面は、そのまま使う。変わるのは **「約定の価格を外から取り込む」部分を「板寄せで決める」に替えること** と、**架空の企業と情報を作ること**。

## 1. 市場

- 架空の取引所で、架空の企業 **12社**（6業種×2社）が上場している。銘柄コードは `TST` で始まらない架空のもの（例：`NEO1`）。社名・業種・発行済株式数・事業の説明は架空
- 1日の流れは今と同じ（営業日、締め 8:30、寄り付き 9:00、引け後の処理）。休場日は今の祝日の一覧を使う（暦だけで、実データではない）
- **1日に1回、寄り付きで板寄せ** をする。その価格がその日の価格（始値＝終値）で、評価にも使う
- 売買単位100株、現物だけ、空売り・信用なし、手数料0円は今のまま

## 2. 注文

- 種類は **指値と成行**。注文票の各注文に、成行か、指値（価格）を書く
- 呼値（価格の刻み）：1円。値幅制限：前日の価格の ±20%（それを超える約定はしない）
- 確定の検査は今のまま（締めの前、約定日、口座の準備、1日1回、銘柄、100株単位、売る株を持っている）。加えて、指値が値幅制限の内側で、呼値に合っていること

## 3. 板寄せ（価格の決め方）

すべての参加者のその日の注文を集め、決まったコードで1つの価格を決める。

1. 候補の価格ごとに、その価格で買える量（その価格以上の買い指値＋成行の買い）と、売れる量（その価格以下の売り指値＋成行の売り）を数える
2. **約定量が最も大きい価格** を選ぶ。並んだら、買いと売りの差（余り）が小さい価格、それも並んだら前日の価格に近い価格、それも並んだら低い価格
3. 約定量が0なら、その日は価格がつかない（前日の価格で評価し、その旨を表示する。注文は失効）
4. 余った側は、**価格の優先（成行→有利な指値）、同じ価格なら注文票の確定時刻の早い順** に約定し、最後の1件は100株単位で一部約定にする
5. 買いの現金が足りないときは、今の規則（買える最大の100株単位まで減らす）を、板寄せの前に当てる（確定時刻の順に、その日の価格で見込まず、**指値（成行は値幅の上限）× 株数** で現金を確かめる）

板寄せは純関数（`src/` の決定論的なコード）で、入力（全員の注文票）と出力（価格・各注文の約定量）を記録し、誰でも作り直せる。

## 4. 参加者

| 種類 | 数 | 動き方 | 記録 |
| --- | --- | --- | --- |
| LLM の AI 投資家 | 5体から | 情報と掲示板を読み、投稿し、注文票を出す（D-041） | `agent.run`・`post.published`・注文票 |
| 規則の AI 投資家 | 3体（今の ミア・リバ・ホールデン） | 規則で注文 | 同上 |
| マーケットメイカー | 銘柄ごとに1 | 架空の「理論価格」のまわりに、買い・売りの指値を毎日出す。在庫が偏ると値をずらす | 注文票（観戦画面のランキングには出さない） |
| ばらばらに売買する参加者 | 数十（まとめて1つのAIとして記録してよい） | 小さい数量の成行・指値を、固定シードの乱数で出す | 同上 |

- マーケットメイカーとばらばらの参加者は、**値がつかない日を減らすための流動性** で、AI 投資家の成績の比較からは外す
- どの参加者も、同じ締めと同じ情報の時刻の規則に従う（先読みしない）

## 5. 企業と情報

- 各社に、架空の業績（四半期の売上・利益・1株利益・配当方針）を **固定シードの乱数のモデル** で作る。業種ごとに成長と変動の大きさを変える
- **決算の開示**：四半期ごとに、決まった日の引け後（15:30）に開示する。開示は新しいイベント（例：`company.disclosed`）で記録し、本文（数字と短い説明）はログの外の値（§5.2）
- 配当・分割は、今の公表と反映の仕組み（`corporate_action.announced` など）をそのまま使う
- マーケットメイカーの「理論価格」は、開示された業績から決まった式で計算する（業績が良ければ上がる）。これで価格が業績から大きく離れ続けない
- ニュース（業界の出来事など）は後で足す

## 6. 実在の世界と混ぜない

- 実在の企業名・実在の銘柄コード・実在の価格・実在の人物を使わない。画面・投稿の全体に「架空の市場です」と出す
- LLM の AI には「架空の市場の架空の企業」であることをプロンプトで伝え、実在の企業の情報を使った投稿は出さない（出典は市場の中の開示と掲示板だけ）

## 8. 作る順番（目安）

1. **core：板寄せの純関数**（§3）と試験。台帳の約定をそれに替える。指値の注文票（§2）
2. **platform：架空の企業と業績のモデル**（§5）、決算の開示、マーケットメイカーとばらばらの参加者（§4）
3. **platform：毎日の実行**（#30）を人工市場で回す。Postgres（#25）に残す
4. **web：** 板寄せの結果（価格・出来高）・企業の開示・業績を画面に出す
5. **platform：LLM の AI**（#29）を足す
6. デプロイ（Vercel・Neon・GitHub Actions、D-040）。**公開できる**（実データを使わないため）。公開の前に、表示と安全の確認（D-039 の公開前の項目のうち、実在の企業に関わらないもの）
